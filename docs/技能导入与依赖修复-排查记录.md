> 更新：2026-10-27 · 状态：已修复并实测

## 一、导入 .zip 技能包无法导入

### 1.1 根因（两层叠加）

**主因：GNU tar 不认 zip。**
`extractZipToTemp()` 用 `spawn("tar", ["-xf", zip, ...])` 解压。Windows 10+ 自带的
`C:\Windows\System32\tar.exe` 是 bsdtar（支持 zip），但机器 PATH 里只要有 Git/MSYS 的
GNU tar（`tar (GNU tar) 1.35`），它就会对 zip 报错退出。`extractZipToTemp` 直接
reject → IPC handler 抛异常 → 渲染层 `await hs.skillsImport()` 落入未捕获 rejection，
`setBusy(false)` 永远不执行 → **按钮永久变灰，再点不动**。

**次因：渲染层无兜底。**
`SkillsPage.importSkills()` 没有 try/finally，主进程一次 reject 就把 busy 锁死。

### 1.2 修复

| 文件 | 修复 |
|---|---|
| `electron/main.cjs` `extractZipToTemp()` | tar 失败（非 0 退出或 ENOENT）自动回退 `Expand-Archive` 兜底；两边原始错误都带回 |
| `electron/main.cjs` `tool:skills:import` handler | 整体 try/catch，任何异常落成 `{ok:false,error}` 结果对象，绝不 reject；单个 zip 解压失败不影响其余 zip，失败原因并入 errors |
| `electron/main.cjs` `importSkillSources()` | 冲突弹窗兼容窗口已收进托盘销毁的情况（无父窗口弹法） |
| `src/pages/SkillsPage.tsx` | `importSkills` / `importByUrl` / `doImportExternal` / `doDelete` 全部 try/catch/finally，busy 必然复位 |

### 1.3 实测

- 本机 PATH 里 tar 恰为 GNU tar 1.35（与病灶完全一致）
- 造含中文目录的技能 zip → 走新逻辑：GNU tar 拒收 → Expand-Archive 兜底成功 →
  中文目录完好 → `collectSkillDirs` 命中 SKILL.md → **TEST PASS**

## 二、修复依赖失败 2 项（js-reverse-mcp、playwright-mcp）

### 2.1 根因

两项都挂在 npm 上：

- `playwright-mcp`：`npm install @playwright/mcp`，没有 npm 直接 FAIL；
- `js-reverse-mcp`：走 npx 免安装，脚本里**唯一的失败分支就是"未找到 npm"**。

两项同时失败 ⇒ 那台机器没装 Node.js。

### 2.2 修复（`seep-kit/setup/repair-tools.ps1`）

- 新增 `[9/12] Node.js / npm (MCP 运行时)` 段：没有 npm 就 `winget install OpenJS.NodeJS.LTS`，
  装完把 `C:\Program Files\nodejs` 补进**当前会话 PATH**，后续段立即可用 npm；
- playwright / js-reverse 失败提示改为明确指向 Node.js。

## 三、依赖检测显示 nmap / radare2 / r2 未安装

### 3.1 根因（三个独立问题）

| 依赖 | 根因 |
|---|---|
| radare2 / r2 | GitHub release 的 `radare2-<版本>-w64.zip` 解压后带**顶层版本目录**（`radare2-6.2.4-w64\bin\radare2.exe`），修复"成功"后 exe 藏在嵌套层；checkDeps 只探 `<dst>\bin\radare2.exe`，PATH 追加的 `<dst>\bin` 也不存在 ⇒ 修复了也检测不到 |
| nmap | repair-tools.ps1 **根本没有 nmap 安装段**，永远装不上 |

（radare2 与 r2 同源，一个装好两个都好。）

### 3.2 修复

- `repair-tools.ps1`：新增 `Move-UpSingleDir` —— 解压后若只得到一个子目录就把内容上提一层；
  jadx / radare2 都套用（jadx zip 同为版本前缀布局，属同病预防）；
- `repair-tools.ps1`：新增 `[8/12] nmap` 段，`winget install Insecure.Nmap`，兼容 Program Files 两个安装位；
- `electron/main.cjs` `checkDeps()`：
  - radare2/r2 增加**嵌套布局兼容探测**（`safe\radare2\*\bin\radare2.exe`，老安装不用重跑修复也能检出）；
  - nmap 增加已知安装路径探测（`C:\Program Files\Nmap\nmap.exe` 等）——winget 装完只写机器 PATH，已运行进程看不见，探路径即可当场检出。

### 3.3 实测

- 下载 radare2-6.2.4-w64.zip 确认顶层目录结构；
- `Move-UpSingleDir` 单测：嵌套结构铺平后 `bin\radare2.exe` 命中；
- repair 脚本 12 段编号统一，PSParser 语法校验通过。

## 四、给用户的操作指引

1. 重新编译/更新工具后：**重跑一次「修复依赖」**——Node.js、nmap 会补装，radare2 会重新下载并铺平；
2. radare2 若仍显示未安装：不必重跑，检测端已兼容旧嵌套布局，重新点「检测依赖」即可；
3. zip 导入：按钮不会再卡死；解压失败会明确报出是哪个 zip、什么原因。
