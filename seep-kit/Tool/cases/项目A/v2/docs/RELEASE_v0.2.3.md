## Seep-Tool v0.2.3 — <项目A> 真·授权激活

### 🎯 根因修复：定位「授权状态字」并给出最小化补丁集

v0.2.1 起「关于」框已能显示自定义授权信息，但宿主仍以试用姿态渲染标题栏与启动欢迎链路。
本次测绘确认：<项目A> 存在**两级解耦的授权变量**——

| 变量 | RVA | 语义 | 是否激活判据 |
|:---|:---|:---|:---|
| `license_type` | `0x22FD724` (int) | 注册码前缀分类 `xy01..xy05` → `1..5` | ❌ 否（仅驱动「关于」框显示） |
| **授权状态字** | **`0x230CDEA` (word)** | **`0xFFFF`=试用 / `0x0000`=已激活** | ✅ **是（真正的开关）** |

状态字由 `NOT(注册加载返回值)` 计算得出（`-1` 通过 → `0`）。
**这正是旧方案「显示授权信息但没成功激活」的失效根因。**

### 🩹 最小化补丁集（4 处确定性指令级热补丁，无需伪造注册码签名）

| # | RVA | 补丁前 → 补丁后 | 作用 |
|:--|:---|:---|:---|
| 1 | `0x670CB1` | `F7 D0` → `31 C0` | `not eax` → `xor eax,eax`，状态字恒为 `0x0000` |
| 2 | `0x670BFF` | `66 C7 00 FF FF` → `66 C7 00 00 00` | 前置检查失败分支不再写试用标记 |
| 3 | `0x670CD5` | `66 C7 00 FF FF` → `66 C7 00 00 00` | 空注册信息分支不再写试用标记 |
| 4 | `0x15E2A47` | `44 8B 5C 24 7C` → `E9 40 00 00 00` | 「关于」框许可等级 → Lifetime License |

28.30.2600 同源补丁点（指令序列完全同构，偏移差 `-0x1039`）：`0x66FC6A` / `0x66FBB8` / `0x66FC8E` / `0x15CEA84`

> 补丁 1-3 生效后，标题栏与启动欢迎链路**无需任何 UI 化妆品补丁**即自然呈现正式授权姿态。

### 🔑 结构化授权码（驱动宿主原生授权元信息呈现）

```
xy05-<用户数>-<4hex>×5-<重复段>-<版本段>
例：xy05-0100-D0F0-3970-185A-1963-A172-D0F0-28.40
```
- 第 2 段 4 位十六进制 = **授权用户数**（`0100` → 1 用户；缺省/非十六进制 → 0 用户）
- 第 9 段 = **版本段**，自动跟随宿主主次版本（`28.40` / `28.30`）
- 其余段为校验无关的自由填充

新增 `BuildLicenseCode()` / `DetectMajorMinor()` / `IsStructuredCode()`，
部署时自动生成并写入宿主 `[Register]` 段。
